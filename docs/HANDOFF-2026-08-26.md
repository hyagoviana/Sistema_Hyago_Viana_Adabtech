## 3. Como mexer neste projeto (armadilhas que custam tempo)

Tudo roda de dentro de **`sistema-hv/`**.

| Tarefa | Comando | Por quê não é o óbvio |
|---|---|---|
| Aplicar migration | `npx tsx scripts/db-apply-pg.ts supabase/migrations/ARQ.sql` | O **Supabase CLI não roda** neste ambiente (Windows + OneDrive). Conexão pg direta é o caminho. |
| Ler o banco | `npx tsx scripts/db-query.ts "select ..."` | — |
| Tipos do banco | **editar `src/lib/supabase/types.ts` à mão** | `npm run db:types` falha (CLI sem auth). Sim, é manual. |
| Build | `NODE_OPTIONS=--max-old-space-size=8192 npm run build` | Sem isso o heap estoura. ~45s com. |
| Typecheck | `npx tsc --noEmit` | — |
| Lint | `npx eslint <seus arquivos>` | **Nunca** `eslint --fix src scripts`: reformata ~119 arquivos alheios. Já aconteceu nesta sessão. |
| Testes | **não existem** | Há 9 arquivos `*.test.ts` e **nenhum runner instalado**. `npm test` não existe. Validação é manual. |

**Ambiente = produção.** Não há banco de dev separado. Migration aplicada é
migration em produção. Toda migration deste ciclo tem rollback simétrico em
`supabase/rollbacks/`.

**Import-protection do TanStack Start:** uma *rota* não pode importar módulo que
puxe `auth-guard` ou `@tanstack/react-start/server`. Quando precisar compartilhar
lógica entre rota e serviço, crie um **módulo puro** — o padrão do projeto são os
`*-shared.ts` (`task-status-shared.ts`, `financeiro-caso-shared.ts`,
`task-types-shared.ts`, `cases/stage-label.ts`).

**Server functions:** o validador recusa `unknown` no retorno. Use `Json`.

**Nunca devolva 5xx** em erro de dependência externa — a Vercel mascara gateway
5xx e a mensagem não chega no front. Use **424**.

## 5. ContaAzul — a frente que está parada

Esta é a parte que precisa de atenção. Leia inteiro antes de tocar em qualquer coisa.

### 5.1 Como a integração funciona hoje

O sistema autentica por **OAuth com refresh token rotativo**. Traduzindo: a cada
renovação, o ContaAzul devolve um refresh token novo e **mata o anterior**.

- O refresh token vive na tabela **`system_integrations`** (`provider = 'conta_azul'`).
- `getAccessToken()` em `src/lib/contaazul/client.ts` lê de lá, renova, e **grava o
  valor novo por cima** — a rotação já é tratada corretamente.
- O **cron diário** (`/api/cron/daily`, `0 9 * * *` UTC) chama `syncContaAzulPagamentos()`,
  o que renova o token todo dia. É isso que mantinha a conexão viva sozinha desde 08/07.

Ou seja: **o mecanismo definitivo já existe e estava funcionando.** Ninguém precisa
inventar nada aqui.

### 5.2 O que quebrou (e por minha culpa)

Havia uma **cópia antiga** do refresh token no `.env.local`, de julho, usada como
fallback. Ao rodar o diagnóstico da FN2, eu peguei essa cópia velha. Provedores com
rotação tratam o reuso de um refresh antigo como **sinal de vazamento e revogam a
família inteira de tokens** — inclusive o que estava bom.

Cronologia, com os dados do banco:

| Quando | O quê |
|---|---|
| 08/07 21:32 | `created_at` do registro — autorização original |
| 26/08 **09:50** | `updated_at` — última renovação **bem-sucedida**, automática |
| 26/08, depois disso | tentativa com o token do `.env` → `invalid_grant` |
| logo em seguida | tentativa com o token **do banco** → `400` |

O token do banco estava vivo às 09:50 e passou a ser recusado depois da tentativa
com o velho. A conclusão mais provável é que a tentativa derrubou a cadeia.

**Consequência:** o sync diário do ContaAzul falha até alguém reautorizar. Nenhum
dado foi perdido — é reconectar.

### 5.3 O que precisa acontecer (só um humano resolve)

**Não é preciso pedir nada ao suporte do ContaAzul.** O `client_id` e o
`client_secret` continuam válidos e o app segue cadastrado. Falta alguém **logado
na conta ContaAzul do escritório** abrir a URL de autorização e aprovar:

```
https://auth.contaazul.com/oauth2/authorize?response_type=code
  &client_id=1admi9jkvanob02avsqqi8q8so
  &redirect_uri=https%3A%2F%2Fwww.sistemahyagoviana.com.br%2Fapi%2Fcontaazul%2Fcallback
  &scope=openid+profile+aws.cognito.signin.user.admin
  &state=shv
```

(sem quebras de linha — a versão colável está em `sistema-hv/docs/contaazul-reautorizar.md`)

O callback `src/routes/api.contaazul.callback.tsx` recebe o `code`, chama
`exchangeCodeForTokens()` e grava no banco sozinho. Aparece "Conta Azul conectada!".

**Se der erro de `scope` ou `redirect_uri`:** o `scope` acima é o padrão do provedor,
não o registro do que foi usado em julho — **não encontrei esse registro em lugar
nenhum do repositório**. Nesse caso, pegar no painel de desenvolvedor do ContaAzul
(1) os escopos que o app declara e (2) as URLs de callback cadastradas, e conferir
que existe exatamente `https://www.sistemahyagoviana.com.br/api/contaazul/callback`.

### 5.4 A blindagem que já foi feita

Em `src/lib/contaazul/client.ts` (não commitado ainda):

- **removido o fallback para `process.env.CONTAAZUL_REFRESH_TOKEN`.** O token vem só
  do banco. Uma cópia velha em arquivo não salva a conexão — ela derruba a que está
  funcionando. O comentário no código explica o porquê para quem vier depois.
- **mensagem de erro que diz o que fazer:** 400/401 na renovação agora responde
  "a autorização caiu — alguém com acesso à conta precisa autorizar o app de novo",
  e não mais "Falha ao renovar token (400)".

### 5.5 O que ainda falta blindar

1. **Apagar `CONTAAZUL_REFRESH_TOKEN`** do `.env.local` e da Vercel. Depois da
   mudança acima ele não é mais lido para autenticar (só para redigir logs), mas
   deixar um segredo morto em arquivo é convite para o mesmo acidente.
2. **Alerta quando a renovação falhar.** Hoje, se cai, ninguém descobre até alguém
   reparar que o financeiro parou de sincronizar. Um aviso na tela de integrações
   ou um e-mail no erro do cron resolve.

## 8. Coisas que vão te morder se você não souber

- **`eslint --fix src scripts` reformata 119 arquivos que não são seus.** Rode o
  eslint só na sua lista de arquivos.
- **Python que escreve arquivo neste repo precisa de `newline=''`** — senão sai CRLF
  e o prettier reprova centenas de linhas.
- **Heredoc de bash com JSX/markdown longo quebra** (`unexpected EOF`). Use a
  ferramenta de escrita de arquivo ou um script salvo.
- **Zod faz strip silencioso.** Campo novo no RPC que você esquecer de declarar no
  schema é **descartado sem erro nenhum**. Aconteceu duas vezes neste ciclo
  (`groupName` na W1, `linkedFieldDefId` na C1). Quando adicionar campo, confira o
  schema do RPC.
- **Multi-ocorrência de campo:** cliente e caso guardam de formas diferentes; a C1
  precisou padronizar em **array na mesma chave**. Se for mexer em campos
  personalizados, leia a `C1` antes.
- **`types.ts` é manual.** Toda migration exige editar `src/lib/supabase/types.ts`
  à mão. Views herdam o `Row` da tabela — não invente bloco novo.
